# PS Fuel 3.6.0 Security Audit Notes

This release was statically reviewed before packaging. This document describes the controls in the source; it is not a claim that a third-party scanner has certified the resource.

## Money and economy authority

- Client callbacks do not receive a generic "give money" endpoint.
- The legacy generic `PSFuelFramework.AddMoney` entry point is disabled.
- Credits use short-lived, one-use server vouchers tied to the character, account, reason and server-approved amount.
- Delivery rewards are generated by the server when the job starts and stored as one-time database claims.
- Delivery claims move atomically from `reserved` to `paying` before a payout and cannot be replayed.
- Robbery rewards, station withdrawals and refund credits have server-side hard ceilings.
- NPC supplier order quantities are clamped on the server. Supplier refunds return to the station ledger instead of creating a client-controlled player-money credit path.
- Fuel purchase litres/kWh are recomputed from the server-validated vehicle/tank profile; the client-supplied physical amount is ignored.
- Vehicle fuel persistence rejects client attempts to increase stored fuel outside the authorized purchase path.

## Station / builder authority

- Station and charger creation requires the configured admin ACE.
- Submitted creation coordinates must be within a small distance of the admin's server-side ped coordinates.
- Capacity and purchase-price values are clamped to server-defined limits.
- IDs are generated by the server.
- Owned-station stock is server/database authoritative.
- Unowned stations can remain full; owned stations are explicitly excluded from automatic restocking.

## Fuel recovery authority

- Siphoning uses a one-time server token.
- Vehicle network entity, plate, player distance and optional engine-off state are revalidated on completion.
- The client never submits the amount to remove.
- The session is consumed before database mutation to prevent replay.

## Outbound HTTP

- The GitHub update check is pinned to `https://api.github.com/repos/deluxehub-design/ps-fuel/releases/latest`.
- Discord webhooks are parsed/validated and the final request uses the fixed Discord webhook origin.
- No client event accepts an arbitrary HTTP URL.

## Recommended deployment validation

Run your normal FiveM resource scanner/ORBIE against the packaged `ps-fuel-v3.6.0` folder after extraction. Any finding should be reviewed using the exact file/line/action reported by the scanner; static scanners may also flag safe server-derived variable payouts, so the source-to-sink path matters.
